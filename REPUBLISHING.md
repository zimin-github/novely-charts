# Что републикует этот фид и на каком основании

`charts/ru.json` раздаётся публично через GitHub Pages. Значит, этот репозиторий
— не просто клиент чужих API, а **републикатор**: всё, что сюда попадает,
становится общедоступным файлом на домене, который не принадлежит источнику
данных. Этот документ — ответ на вопрос «какие данные вы перевыкладываете и на
каком основании», отдельно по каждому источнику.

Дата аудита: 5 октября 2026. Контакт: `app.zimin@gmail.com`.

## Коротко

| Источник | Републикуется в фиде | Основание |
|---|---|---|
| Open Library (Internet Archive) | Да: название, авторы, год, число страниц, ISBN, ключ произведения/издания, URL обложки | Данные каталога Open Library выпущены в общественное достояние (CC0). Обложки не копируются — на них стоит ссылка на `covers.openlibrary.org` |
| Кураторские списки Novely | Да: сам список названий и авторов | Наш собственный редакционный выбор |
| Google Books API | **Нет. Удалено** | Условия Google Books API не дают права хранить их контент и раздавать его с чужого домена |
| Обложки как файлы | Нет: только URL | Изображения не скачиваются и не переразмещаются |

## Что было не так до 5 октября 2026

Сборщик работал в три яруса: чарт Open Library → предметный индекс Google Books
→ кураторский список, тоже разрешавшийся через Google Books. То есть **два из
трёх ярусов писали данные Google Books в публичный файл**:

* в фид попадали `volumeInfo.title`, `authors`, `description`, `publishedDate`,
  `industryIdentifiers`, `pageCount` и `imageLinks` — то есть содержимое выдачи
  Google, а не ссылка на неё;
* `id` в фиде — это идентификатор тома Google Books;
* `coverURL` указывал на `books.google.com/books/content?id=…`, то есть
  изображения Google раздавались как обложки в приложении;
* при этом `infoLink` / `canonicalVolumeLink` в фид **не переносились**, поэтому
  у книг с таких полок физически не было ссылки на страницу тома в Google
  Books — а правила брендинга Google требуют её рядом с их данными;
* в самом файле не было ни слова об источнике и условиях.

Это ровно то, что в условиях называется использованием API как
неконтролируемого массового бэкенда: ночной job, который складывает чужой
каталог в свой файл и раздаёт его неограниченному числу клиентов без
атрибуции. На момент аудита опубликованный `charts/ru.json` содержал такие
записи на полках `newReleases` и `nonFiction` (`"source": "curated"`).

## Что сделано

1. **Google Books удалён из сборщика полностью.** Функции `google_search`,
   `to_book`, `google_chart`, `resolve_seed` (его Google-версия) и таблица
   `GOOGLE_SUBJECTS` убраны; переменная `GOOGLE_BOOKS_KEY` больше не читается, а
   секрет убран из workflow. Ни один сетевой запрос этого репозитория не идёт в
   `googleapis.com`.
2. **Кураторские списки разрешаются через Open Library** (`resolve_seed`). Если
   издание не нашлось — оно просто выпадает, и полка становится короче.
3. **Ярусов стало два:** чарт Open Library (`"source": "openlibrary"`) и
   кураторский список Novely (`"source": "curated"`). Значение `"googlebooks"`
   больше не производится; приложение по-прежнему умеет его прочитать, потому
   что на телефонах может лежать закэшированный старый фид.
4. **В payload добавлен блок `attribution`** — источник, лицензия, статус
   обложек, статус Google Books и контактный адрес.
5. **Запросы к Open Library приведены в порядок:** User-Agent с названием
   приложения, версией и контактным адресом (`NOVELY_CONTACT_EMAIL`), пауза не
   меньше секунды между запросами к одному хосту, локальный кэш на 12 часов
   (сиды повторяются в разных жанрах — «Атомные привычки» встречаются в трёх), и
   обработка 429/503 с уважением к заголовку `Retry-After`. Пул потоков из двух
   воркеров убран — запросы идут последовательно.

## Как Google Books используется теперь

Только в приложении, живьём, по действию читателя:

* поиск — один запрос, одна выдача, в порядке Google, со знаком «Powered by
  Google» и без примеси других источников;
* обложки, описания и разрешение кураторских сидов внутри приложения;
* на экране книги — ссылка «Смотреть на Google Books» на страницу тома.

Ничто из этого не кэшируется на сервере и не републикуется. Подборки, которые
Novely собирает сама (рекомендации, «по вашим осям», кураторские полки),
подписаны как собственные и знаком Google не отмечаются.

## Что осталось открытым

* **Обложки `covers.openlibrary.org`** загружаются самим приложением напрямую в
  `AsyncImage`, то есть без нашего User-Agent и вне ограничителя частоты
  запросов. Технически это обычная загрузка картинки по URL; формально это
  трафик к Internet Archive, который мы не считаем. Вопрос вынесен в список для
  письменного обращения.
* **Объём кураторских полок.** Open Library находит русские издания хуже, чем
  Google по названию и автору, поэтому часть сидов может не разрешаться и полки
  будут короче. Это осознанный обмен: короткая полка из данных, которые можно
  републиковать, лучше полной из тех, которые нельзя.
