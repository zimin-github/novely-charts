# Novely Charts

Статический фид книжных подборок для приложения Novely.

Главные полки «Открытий» не собираются на телефоне из Open Library: этот хост
принадлежит Internet Archive и недоступен из ряда сетей. Здесь семь домашних
полок собираются на GitHub, а приложение скачивает один статический файл через
GitHub Pages. Поиск и дополнительные жанровые экраны Novely могут обращаться к
Google Books и Open Library напрямую.

**Адрес фида:** `https://zimin-github.github.io/novely-charts/charts/ru.json`

## Как это работает

1. `build_charts.py` собирает полки в три уровня, сверху вниз, пока не наберётся
   хотя бы 6 книг:
   1. **чарт Open Library** — рейтинг по читательской активности, лучший
      вариант, когда источник отвечает (`"source": "openlibrary"`);
   2. **предметный индекс Google Books** — не рейтинг, но всегда доступен и
      реально обновляется: `subject:` + `orderBy=newest`
      (`"source": "googlebooks"`);
   3. **кураторский список** из `GENRES` — последний резерв
      (`"source": "curated"`).
2. GitHub Actions запускает скрипт ежедневно в 04:00 UTC и коммитит результат.
3. GitHub Pages раздаёт `charts/ru.json` по HTTPS.
4. Приложение скачивает файл, кэширует его и показывает подборки. Если файл
   недоступен — работает встроенный резерв, экран пустым не будет.

## Настройка GitHub

Репозиторий и Pages уже опубликованы. Для восстановления или переноса настройки:

1. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/`.
2. **Settings → Secrets and variables → Actions → New repository secret**:
   имя `GOOGLE_BOOKS_KEY`, значение — ключ Google Books.
3. **Actions → Update charts → Run workflow** — проверить прогон.
4. Сверить адрес с `ChartFeedService.feedURL` в приложении.

## Что требует внимания потом

Полностью «настроил и забыл» не бывает, но обслуживания здесь минимум:

- **GitHub отключает cron в репозитории без активности 60 дней.** Так как бот
  коммитит файл при каждом изменении, активность есть. Если полки не менялись
  два месяца подряд — зайти и нажать Run workflow.
- **Если источник поменяет формат ответа**, скрипт не упадёт, а спустится на
  уровень ниже. Признак — `"source"` во всех полках сразу: `googlebooks`
  означает, что Open Library недоступна (полки всё ещё обновляются каждый день);
  `curated` — что и Google не ответил, и полки застыли. Второе стоит проверять,
  первое — нет.
- **Кураторские списки в `GENRES`** стоит освежать примерно раз в полгода,
  чтобы «Новые книги» не устаревали.

## Локальный запуск

```bash
GOOGLE_BOOKS_KEY=ваш_ключ python3 build_charts.py
```

На macOS со сборкой Python с python.org может понадобиться указать хранилище
сертификатов: `SSL_CERT_FILE=/etc/ssl/cert.pem`.

## Формат

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-08-14T16:24:30Z",
  "shelves": {
    "popular": {
      "title": "Популярное",
      "source": "openlibrary",   // также "googlebooks" или "curated"
      "books": [
        {
          "id": "…", "title": "…", "authors": ["…"],
          "publishedDate": "…", "description": "…", "isbn": "…",
          "coverURL": "https://…", "totalPages": 0
        }
      ]
    }
  }
}
```

Каждый ключ опубликованной полки совпадает с соответствующим
`DiscoverGenre.rawValue`; фид содержит семь основных полок, а не все 15 жанров
приложения. При изменении структуры нужно поднять `schemaVersion` — приложение
игнорирует фид с незнакомой версией и показывает встроенный резерв.
