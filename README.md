# Novely Charts

Статический фид книжных подборок для приложения Novely.

Главные полки «Открытий» не собираются на телефоне из Open Library: этот хост
принадлежит Internet Archive и недоступен из ряда сетей. Здесь полки собираются
на GitHub, а приложение скачивает один статический файл через GitHub Pages.
Поиск и дополнительные жанровые экраны Novely обращаются к Google Books и Open
Library напрямую, из приложения.

**Этот фид публичный, поэтому в нём только то, что можно републиковать:** данные
Open Library (CC0) и собственные кураторские списки Novely. Google Books из
сборщика убран полностью — см. [REPUBLISHING.md](REPUBLISHING.md).

**Адрес фида:** `https://zimin-github.github.io/novely-charts/charts/ru.json`

## Как это работает

1. `build_charts.py` собирает полки в два уровня, сверху вниз, пока не наберётся
   хотя бы 6 книг:
   1. **чарт Open Library** — рейтинг по читательской активности, лучший
      вариант, когда источник отвечает (`"source": "openlibrary"`);
   2. **кураторский список** из `GENRES`, издания для которого находятся в Open
      Library (`"source": "curated"`). Приложение подписывает такую полку как
      подборку Novely, а не как чей-то чарт.

   Третьего уровня — предметного индекса Google Books — больше нет: его выдача
   попадала в публичный файл, а на это условия Google Books API права не дают.
2. Запросы к Open Library идут с User-Agent, в котором указано приложение,
   версия и контактный адрес (`NOVELY_CONTACT_EMAIL`), не чаще одного в секунду,
   с локальным кэшем на 12 часов и с паузой по `Retry-After` при 429/503.
3. GitHub Actions запускает скрипт ежедневно в 04:00 UTC и коммитит результат.
4. GitHub Pages раздаёт `charts/ru.json` по HTTPS.
5. Приложение скачивает файл, кэширует его и показывает подборки. Если файл
   недоступен — работает встроенный резерв, экран пустым не будет.

## Настройка GitHub

Репозиторий и Pages уже опубликованы. Для восстановления или переноса настройки:

1. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/`.
2. Секреты не нужны: ключ Google Books больше не используется, его можно удалить
   из Settings → Secrets. Контактный адрес для User-Agent задан в workflow
   переменной `NOVELY_CONTACT_EMAIL`.
3. **Actions → Update charts → Run workflow** — проверить прогон.
4. Сверить адрес с `ChartFeedService.feedURL` в приложении.

## Чего в фиде нет

`newReleases` («Новые книги») и `nonFiction` («Нон-фикшн») из этого фида не
приходят, и это не поломка, которую нужно починить здесь.

У `newReleases` нет живого чарта (`"openlibrary": None`), а `nonFiction`
по `subject:self-help` отдаёт три книги из нужных шести, так что обе полки
падают на кураторский ярус. А он с 5 октября 2026 разрешается через Open
Library — и не разрешается: из двадцати сидов двух полок не находится ни один.
Это не придирчивый фильтр, а отсутствие данных. «Атомные привычки» и «Петровы в
гриппе» не дают в Open Library ни одного документа вообще; Прилепин там есть
только латинской транслитерацией (`Sanʹki︠a︡`, `Vosʹmerka`), а такое название
русской полке не годится, поэтому `openlibrary_to_book` его отбрасывает.
Переписывать сиды бессмысленно: искать нечего.

Эти полки наполняет приложение — живым запросом в Google Books, по открытому
экрану читателя, и подписывает их как подборку Novely
(`fillShelvesMissingFromFeed` в `GoogleBooksService`). Условия Google Books
такое разрешают; складывать их выдачу в этот публичный файл — нет, см.
[REPUBLISHING.md](REPUBLISHING.md).

## Что требует внимания потом

Полностью «настроил и забыл» не бывает, но обслуживания здесь минимум:

- **GitHub отключает cron в репозитории без активности 60 дней.** Так как бот
  коммитит файл при каждом изменении, активность есть. Если полки не менялись
  два месяца подряд — зайти и нажать Run workflow.
- **Если источник поменяет формат ответа**, скрипт не упадёт, а спустится на
  уровень ниже. Признак — `"source": "curated"` во всех полках сразу: значит,
  Open Library не отвечает и полки держатся на кураторских списках. Это стоит
  проверять.
- **Кураторские списки в `GENRES`** стоит освежать примерно раз в полгода,
  чтобы «Новые книги» не устаревали. Правятся они здесь, но работают на
  телефоне: сиды `newReleases` и `nonFiction` разрешает приложение, а не этот
  сборщик, и те же списки лежат в `DiscoverGenre.curatedSeeds`.

## Локальный запуск

```bash
NOVELY_CONTACT_EMAIL=вы@example.com python3 build_charts.py
```

Прогон занимает минуты, а не секунды: между запросами выдерживается пауза.
Повторные запуски быстрее — ответы лежат в `.cache/` 12 часов.

На macOS со сборкой Python с python.org может понадобиться указать хранилище
сертификатов: `SSL_CERT_FILE=/etc/ssl/cert.pem`.

## Формат

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-08-14T16:24:30Z",
  "attribution": { /* источник, лицензия, статус обложек и Google Books */ },
  "shelves": {
    "popular": {
      "title": "Популярное",
      "source": "openlibrary",   // или "curated"
      "books": [
        {
          "id": "…", "title": "…", "authors": ["…"],
          "publishedDate": "…", "description": "…", "isbn": "…",
          "coverURL": "https://…", "totalPages": 0
        }
      ]
    }
  }
}
```

Каждый ключ опубликованной полки совпадает с соответствующим
`DiscoverGenre.rawValue`. В `GENRES` описаны все 15 жанров приложения, но в
файле оказывается только то, что собралось: полка, которая не дала ни одной
книги, выбрасывается, а не публикуется пустой. Сколько полок вышло, видно в
логе прогона и в самом файле.

Две полки не собираются здесь никогда — см. «Чего в фиде нет». При изменении
структуры нужно поднять `schemaVersion` — приложение игнорирует фид с
незнакомой версией и показывает встроенный резерв.
